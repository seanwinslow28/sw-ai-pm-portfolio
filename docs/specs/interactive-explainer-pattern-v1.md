## 0. TL;DR

The static `animation-pipeline` explainer (a flat `.webp` diagram) became an interactive figure: a real graphite **run cycle** of an anonymous animator's gesture figure that the reader **inks in by scrubbing a 10-phase timeline**. The human keyframe (leftmost figure) is already drawn; dragging sweeps a soft "drawing" edge left-to-right, the fleet inking the in-between poses, until the shipped frame lands with a stamp-amber approval stamp. It is the portfolio's thesis — *"the agents handle the loops, I handle the taste"* — made tactile: the reader performs the fleet's job.

The art is generated by **Gemini Nano Banana 2** as a single run-cycle sheet (one generation = consistent identity/style), keyed to transparent so it sits on the site's real cream paper. Graphite throughout (authentic); the HUMAN / FLEET / SHIP color story lives in the labels + the stamp. Progressive-enhancement: no-JS / `prefers-reduced-motion` shows the complete run with the scrubber hidden.

**File manifest** — see §10. **Reproduce / extend to the other explainers** — see §11.

## 1. Where this came from (the request)

Sean asked whether the new **Claude Artifacts** update (the attached Claude Code doc) let him put artifacts on the portfolio, or whether to make animated explainers in **Claude Design**, and which would grab recruiters better.

Web-verified findings that shaped the answer:
- The attached doc is **Claude *Code* Artifacts** — Team/Enterprise, **org-only sharing** ("no option to make an artifact viewable outside it"). Not publicly embeddable. Escape hatch the doc itself names: "ask Claude for the HTML file and share that file directly."
- **claude.ai *chat* Artifacts** *do* support public sharing + iframe embed (a "Get embed code" button, allowed-domains field; free tier since Feb 2026).
- **Claude Design** (Anthropic Labs, ~Apr 2026) generates production-ready HTML/CSS/JS including animation, and the output is **deployable code you can host**.

**Recommendation (and why):** do **not** iframe a live Claude artifact onto the portfolio. Three reasons specific to this site: (1) a live artifact runs on Anthropic's `*.claudeusercontent.com` under a strict CSP that blocks external fonts/assets — it can't pull Newsreader / JetBrains Mono / the paper-teal palette, so it reads as a foreign object; (2) Claude chrome on *Sean's* page undercuts "I handle the taste"; (3) a runtime iframe that fails is a dead band on a recruiter's screen. **Use the AI tools as the *authoring* path, then commit the exported, self-hosted code** — on-domain, on-brand, no third-party runtime. Format pick: lightweight inline SVG / keyed raster, never Three.js (respects the DESIGN.md stack ban on GSAP/Framer/Lenis).

## 2. The brainstorm (what we decided to build, and why)

Ran `pm-product-discovery:brainstorm` (mode: *ideas, existing product*), multi-perspective (PM / Designer / Engineer). Scope was set by a short elicitation — Sean chose: **pilot one explainer first**, **interactive**, **ambition ~3** (balanced, not a Three.js showpiece), lead with **animation-pipeline**, keep it lightweight, and let "how it was made" be a reach-out talking point rather than on-page copy.

Convergence (top ideas): **scrub-to-tween** (the reader fills the in-betweens — *is* the thesis, made tactile) + **pencil-draws-itself** (so it reads as animation, not a slider) + **phase reveal on hover**, built as **inline SVG, zero deps**, **static-first** for reduced-motion. The losing alternative — embedding a live artifact — was rejected for the §1 reasons.

Full brainstorm output is in the session history; the load-bearing decisions are captured here and in §8.

## 4. Inspiration wells

- **Onion-skinning / the animator's lightbox** — the single most on-brand idea. Ghosted in-between frames under the active drawing *is* what an animator sees, and it's literally what the anima pipeline generates. The "faint ghost of the whole run + ink it in" reveal is this.
- **The 12 principles** (Thomas & Johnston, *The Illusion of Life*) — slow-in/slow-out, arcs, timing vs spacing. Same well `2d-animation-principles` draws from.
- **Bartosz Ciechanowski** — the gold standard for drag-to-understand, library-free, scrubbable explainers. The "scrub to understand" model.
- **Newsroom interactive graphics** (NYT graphics desk, The Pudding) — fits the portfolio's dateline / wire-service identity. The explainer as a small piece of newsroom interactive journalism.
- **mynrd.co.uk** — PRODUCT.md's named aesthetic anchor ("the right lane"): hand-drawn character, torn paper, comedic-confident, motion *restraint*.

## 5. The two pivots (the honest path)

1. **Procedural SVG first.** v1 built the figures as parametric forward-kinematics skeletons (one stroke per bone, head circle), scrubbed via per-figure opacity (onion-skin). It worked and verified clean, but read as **stick figures** — one ruler-straight stroke per bone, no construction, no volume.
2. **Sean wanted *actual sketches*.** Offered a procedural pencil-rough upgrade (construction lines + searching strokes + an SVG roughen filter) **vs** real AI-drawn sketches. Sean chose **real AI sketches, anonymous animator gesture**.
3. **Within the AI path:** single keyed sheet + **continuous ink-in wipe** (chosen) vs 7-frame discrete onion-skin. The wipe won — one asset, preserves the artwork's spacing, and the left-to-right sweep *is* the human→fleet→ship metaphor.

The procedural `AnimationPipelineExplainer.astro` was fully replaced by the raster version in step 3. If a future session wants the procedural pencil-rough technique (construction underdrawing + `feTurbulence` graphite roughen), it's described in the session history but not in the repo.

## 6. Generating the art — Gemini Nano Banana 2

**Model:** `gemini-3.1-flash-image-preview` (Nano Banana 2), via the `gemini-pencil-animation-image-gen` skill's `generate_image.py` (uses `google-genai`).

**Consistency strategy — one sheet, not seven calls.** The hard problem is keeping a figure identical across frames (the exact problem anima exists to solve). We sidestepped it: generate **one run-cycle sheet** — 7 progressive running poses in a single horizontal row — so a single generation yields consistent identity, style, scale, and ground line for free. (This also makes the left-to-right wipe trivial.)

**Prompt** (committed verbatim in [`scripts/gen-explainer-runcycle.sh`](../../scripts/gen-explainer-runcycle.sh)): an anonymous, gender-neutral, feature-less gesture figure (so it reads as *process*, not a character), side profile running right, **warm gray graphite (not black ink)**, **visible construction guide lines** (gesture line of action, ribcage/pelvis ovals, joint circles), loose searching strokes, on a **plain flat off-white background** (no paper chrome / hole-punches / labels — we wanted clean keyable line art, since the portfolio's *own* paper supplies the warmth). Negatives explicitly bar color, ink-black, anime, cel-shading, vector-clean lines, scenery, and a ground shadow.

**The sandbox can't reach the image API.** The cowork sandbox routes network through a SOCKS proxy that **403s `generativelanguage.googleapis.com`** (pip/pypi work; the Google host is not allowlisted). We did **not** route around it. Instead:
- The generator is committed as [`scripts/gen-explainer-runcycle.sh`](../../scripts/gen-explainer-runcycle.sh) (it uses the anima repo's `gemini-pencil-animation-image-gen` skill + its `GEMINI_API_KEY`).
- Sean ran `bash scripts/gen-explainer-runcycle.sh` **locally** (where the API is reachable); the raw PNG landed in the portfolio's `public/assets/...` (a mounted folder), and the agent picked it up from there for keying + wiring.

This **generate-locally → key-and-wire-in-session** split is the reusable pattern whenever an asset needs an API the sandbox can't reach. (Side note: `google-genai` over the SOCKS proxy needs `pip install "httpx[socks]" socksio`.)

## 7. Keying graphite → transparent

The raw sheet is graphite on cream (1376×768). To composite it on the portfolio's real paper, we key it to transparent with **luminance → alpha** (committed as [`scripts/key-explainer-art.py`](../../scripts/key-explainer-art.py)):

- `alpha = clamp((paperL − pixelL) × gain)` — darkness becomes opacity, so the page-white goes transparent while every graphite stroke keeps its natural weight (lighter line = lower alpha). This is why a magic-wand cut was *not* used: it leaves halos and eats the faint **construction lines** we wanted to keep.
- An **alpha floor** (`< 36 → 0`) removes paper grain and the faint printed ground line in the same pass (addresses Sean's "remove the bottom line").
- RGB is set to a **uniform warm graphite** `(50,48,45)` so anti-aliased edges carry no cream tint (no halos); alpha alone carries the value variation.
- Trim to content bbox (+24px pad).

Output: a **1376×457 transparent WebP, 68 KB lossless** at `public/assets/projects/explainers/animation-pipeline-runcycle.webp`. No splitting into 7 frames was needed.

## 8. The interaction — continuous ink-in wipe

Two layers of the same keyed sheet, in [`AnimationPipelineExplainer.astro`](../../src/components/case-study/AnimationPipelineExplainer.astro):

- **Ghost layer** — the whole run at `opacity: 0.15`, always visible (you see where the run is going).
- **Ink layer** — full opacity, revealed by a CSS `mask-image: linear-gradient(to right, #000 calc(--reveal − 5%), transparent --reveal)`. A tiny script sets `--reveal` from the scrub value with an **ease-in/out** curve (honoring the spacing principle — not a linear sweep).
- **`BASE = 15%`** — the reveal starts at ~15%, so the **human keyframe (leftmost figure) is already inked** at `t=0`. Scrubbing inks the rest (the fleet's job).
- **Pencil** rides the reveal edge (`left: var(--reveal)`), a small graphite pencil SVG (monochrome — no amber-mid on paper).
- **Stamp-amber approval stamp** fades in near `t≈1` (a loose circle + check), landing on the shipped frame.
- **Labels** below: HUMAN (`--ink`) / FLEET (`--teal`) / SHIP (`--success-teal`) with mono sublabels — color-as-actor lives here, while the drawing stays authentic graphite.
- **Scrubber**: a native `<input type="range">` styled as the 10-phase timeline (keyboard-operable for free), shown only in interactive mode.

**Progressive enhancement / reduced-motion:** the script no-ops under `prefers-reduced-motion` and never runs without JS. Default state = `--reveal: 100%` (complete run drawn) + scrubber hidden + stamp shown. The interactive collapse to `BASE` happens only when JS opts in (`is-interactive`).

## 9. Design-system fit (DESIGN.md / PRODUCT.md)

- **Color-as-actor on real tokens:** `--ink` keyframe / `--teal` in-betweens / `--success-teal` shipped (the literal SHIPPED token) in the labels; `--stamp-amber` for the approval stamp (never amber-mid on paper — the Inversion Rule).
- **Flat, sharp:** no shadows, `1px` sharp range thumb, no glass.
- **Motion:** `--ease-out` is the house hover curve; the scrubber is a *functional affordance* gated behind interaction, consistent with the **Licensed-Infinite-Motion Rule** (cf. `swipe-me-bob`). Nothing animates forever.
- **CLS:** `.api-stage { aspect-ratio: 1376/457 }` reserves height before paint.
- **Accessibility (PRODUCT.md WCAG AA):** the ink `<img>` carries the full `alt` (the rich description from frontmatter); the ghost is `aria-hidden`; the range has an `aria-label` and a stamp-amber `:focus-visible` ring; decorative ticks/labels/pencil/stamp are `aria-hidden`. Reduced-motion lands on the complete state, matching the spec's "renders solid at final color."

## 11. Reproduce / extend to the other four explainers (playbook)

The component is currently hard-wired to `animation-pipeline` (one asset path, fixed labels). To roll the pattern out:

1. **Brainstorm the metaphor** for the project (each explainer should dramatize *that* system, not be generic motion). Keep ambition modest; lightweight beats Three.js.
2. **Write the run-cycle / sequence prompt** in the style of `scripts/gen-explainer-runcycle.sh` — clean graphite line art, **plain light background** (no paper chrome), explicit negatives.
3. **Generate locally:** `bash scripts/gen-explainer-runcycle.sh` (adapt the prompt + `OUT` path). Re-roll a couple of takes; image gen varies. The sandbox cannot reach the Gemini API — this step is always local.
4. **Key it:** `python3 scripts/key-explainer-art.py IN.png public/assets/projects/explainers/<slug>-runcycle.webp` (tune `--alpha-floor` / `--dark-anchor` if the source contrast differs).
5. **Generalize the component first.** Before the second project, refactor `AnimationPipelineExplainer.astro` into a parameterized `InteractiveExplainer.astro` taking `src`, `alt`, the three zone labels, and `base`. Then `explainer.interactive` becomes the variant key (or carry the params in frontmatter). Don't copy-paste the component five times.
6. **Wire:** set `explainer.interactive` in the project's `.mdx`; the `ExplainerGraphic` branch already exists (extend the condition).
7. **Verify:** `npm run dev` → the case-study route. Run `design:accessibility-review`. Confirm reduced-motion (full sheet, no scrubber) and CLS.

## 12. Caveats / open items / tuning knobs

- **Live build not run in-session.** The sandbox has no `node_modules` and can't reach the Gemini API. The visual was verified via exact-math Python mocks; **`npm run dev` / `npm run build` must be run on Sean's machine** to confirm the live render. Low-risk standard Astro, but unconfirmed.
- **Raw sheet cleanup.** `public/assets/projects/explainers/animation-pipeline-runcycle-raw.png` (~470 KB) is still in `public/` (the sandbox couldn't delete it — mount permissions). Safe to `rm`; it's reproducible via the generator script.
- **Tuning knobs:** `BASE` (15% — how much keyframe is pre-inked), ghost `opacity: 0.15`, mask soft edge (`5%`), and keying `--dark-anchor` / `--alpha-floor`.
- **Component is per-project** — generalize before rollout (§11 step 5).
- The static `animation-pipeline.webp` remains the `src` fallback in frontmatter; keep it.

## 13. Lessons for future sessions

- **Show, don't tell.** Every fork was resolved by rendering a faithful preview (Python mocks of the exact CSS-mask math), not by describing it. Cheap, and it made the recommendations concrete.
- **Procedural-first was the wrong read for "sketch."** Clean FK vectors read as stick figures; the user wanted *drawings*. When "feels hand-made" is the bar, real art (or heavy roughen) beats clean geometry.
- **Consistency via one sheet.** For multi-frame character art, one generation of a sequence sheet beats N chained calls — it dodges the identity-drift problem outright.
- **Network blockers → generate locally, process in-session.** When the sandbox can't reach an API, commit the generator, have the user run it (output to a mounted folder), and pick it up. Don't try to tunnel.
- **Keep the AI output on Sean's domain.** Author with Claude Design / artifacts / Nano Banana; ship the exported, self-hosted code. The honesty layer works because the output is *his*.

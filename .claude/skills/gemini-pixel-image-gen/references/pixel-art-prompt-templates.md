# Pixel Art Prompt Templates for Agent Control Center

> **When to read:** Always read this file when generating pixel art assets. Contains ready-to-use prompt templates aligned with the [pixel-agents](https://github.com/pablodelucca/pixel-agents) asset format so custom sprites and backgrounds are structurally compatible.

---

## pixel-agents Asset Architecture

All templates in this file produce assets that match the pixel-agents rendering engine. Key specs:

| Parameter | Value | Notes |
|-----------|-------|-------|
| **Projection** | Top-down orthogonal (NOT isometric) | No vanishing point, no angled perspective |
| **Tile size** | 16x16 pixels | Every floor, wall, and furniture piece aligns to this grid |
| **Character sprite size** | 16x32 pixels (W x H) | Characters are 1 tile wide, 2 tiles tall |
| **Rendering** | Canvas 2D, pixel-perfect | Integer zoom, no sub-pixel blending |
| **Grid** | Up to 64x64 tiles | Default office layout is ~21x22 tiles |
| **Depth sorting** | Y-position based | Lower rows render in front of higher rows |
| **Character palettes** | 6 palettes via HSL hue-shifting | Base sprite is recolored dynamically (45°-316° hue range) |
| **Zoom** | 1x-10x integer steps | Sprites cached at each zoom level |

### Character Animation States

The pixel-agents state machine has **3 core states** with sub-animations:

| State | Animation | Frames | Frame Duration | Trigger |
|-------|-----------|--------|----------------|---------|
| `IDLE` | Subtle breathing | 2-4 | 0.15s | Character waiting, no active task |
| `WALK` | Walk cycle | 4 (pattern: 0,1,2,1) | 0.15s | Moving to seat or wandering |
| `TYPE` | Typing at desk | 2 | 0.15s | Active task — code generation tools |
| `TYPE` → `READ` | Reading at desk | 2 | 0.15s | Active task — Read, Grep, Glob, WebFetch, WebSearch tools |

Walk speed is 48 pixels/second. Characters face 4 directions: DOWN, UP, RIGHT, LEFT (LEFT is generated by flipping RIGHT horizontally).

### Character Behavior Timers

| Behavior | Duration | Notes |
|----------|----------|-------|
| Wander pause | 2-20 seconds | Random idle between roaming moves |
| Seat rest after activity | 120-240 seconds | Character sits before wandering again |

### Furniture Manifest Format

Each furniture item has a `manifest.json` that tells the renderer how to use the sprites:

```json
{
  "name": "DESK",
  "sprites": {
    "DESK_FRONT": { "file": "DESK_FRONT.png", "anchor": "bottom-center" },
    "DESK_SIDE": { "file": "DESK_SIDE.png", "anchor": "bottom-center" }
  },
  "canMirror": true,
  "seatOffset": { "x": 0, "y": -8 }
}
```

Furniture can be mirrored horizontally via `ctx.scale(-1, 1)`. Seat offsets define where a character sits relative to the furniture anchor.

### Character Palette Approach

Pixel-agents recolors a single base sprite using HSL hue-shifting. For YOUR custom characters (based on reference photos of real people), you have two approaches:

**Approach A: Unique sprites per person (recommended for recognizable people)**
Generate a completely distinct 16x32 sprite for each person. Use reference photos to capture distinguishing features (hair color/style, skin tone, clothing). Each character gets their own PNG file.

**Approach B: Base sprite + hue-shift (for generic/additional characters)**
Generate one base sprite and let the renderer recolor it. Good for background characters or extras, not for recognizable individuals.

## Template 1: Custom Character Sprite (From Reference Photo)

Use when generating a pixel art sprite of a specific real person for the Agent Control Center.

```
Create a pixel art character sprite based on the person in the reference photo.

Dimensions: EXACTLY 16 pixels wide by 32 pixels tall. This is critical — the sprite
must fit a 16x32 pixel grid precisely.

Perspective: Front-facing (looking toward the camera/viewer), top-down orthogonal
view — NOT isometric, no angle. The character stands on a flat plane viewed straight on.

Character: Capture the key distinguishing features of the person in the reference photo:
- Hair: [COLOR, STYLE, LENGTH from photo]
- Skin tone: [APPROXIMATE from photo]
- Clothing: [DESCRIBE what they're wearing or choose an outfit — e.g., "dark hoodie and jeans", "green t-shirt and shorts"]
- Build: [GENERAL body type]

Pose: Standing idle, arms at sides, slight relaxed posture. This is the base idle frame.

Style: 16-bit pixel art. Clean dark outlines (#272929, 1px at this scale).
Each pixel must be a distinct, visible square — this is true pixel art at 16x32 resolution,
not a shrunken illustration. Every detail must be expressed in individual pixels.

Technical requirements:
- Transparent background (no floor, no shadow, no environment)
- 1:2 aspect ratio (16 wide, 32 tall)
- No anti-aliasing. No gradients. No sub-pixel blending.
- No blur. Crisp, hard pixel edges only.
- Character should fill most of the 16x32 canvas (feet near bottom, head near top)
```

### Generating All 3 Directions

The pixel-agents renderer needs DOWN, UP, and RIGHT facing sprites (LEFT is auto-generated by flipping RIGHT). Generate each direction separately:

**Front-facing (DOWN):** Character faces the viewer. This is the primary sprite.

**Back-facing (UP):** Character faces away from the viewer. Same clothing, hair visible from behind.

**Right-facing (RIGHT):** Character faces to the right in profile. Same proportions, same outfit.

For each direction, append to the base prompt:
```
Direction: [FRONT-FACING / BACK-FACING / RIGHT-FACING PROFILE].
Maintain identical proportions, clothing, and color palette as the other direction sprites
for this character. The silhouette height and width must be consistent across all directions.
```

## Template 2: Character Sprite Sheet (Animation Frames)

Use when generating a full animation sheet for one character. This produces all frames needed for the pixel-agents state machine.

```
Create a pixel art sprite sheet for a single character with all animation frames.

Character: [DESCRIPTION or "matching the character from the reference photo"]

Sheet layout: A horizontal strip organized as follows. Each frame is EXACTLY 16x32 pixels.
Frames are arranged left-to-right with NO gaps between them.

Frame sequence (left to right):
- Frames 1-4: WALK cycle facing DOWN (toward viewer). Pattern: stand, step-left, stand, step-right.
- Frames 5-8: WALK cycle facing UP (away from viewer). Same step pattern.
- Frames 9-12: WALK cycle facing RIGHT (profile). Same step pattern.
- Frames 13-14: TYPING animation facing DOWN. Hands alternate position on keyboard.
- Frames 15-16: READING animation facing DOWN. Character holds document or looks at screen.
- Frames 17-18: IDLE breathing facing DOWN. Subtle chest/shoulder rise and fall.

Total: 18 frames at 16x32 each = final image is 288x32 pixels.

Style: 16-bit pixel art. Clean dark outlines (#272929, 1px).
Consistent identity across EVERY frame — same hair, skin, clothing, proportions.
Each frame must align perfectly to the 16-pixel column grid.

Technical:
- Transparent background
- No anti-aliasing. No gradients. No blur.
- Feet should land at the same Y position across all frames (consistent ground line)
- Walking frames should show clear leg movement with the 0-1-2-1 pattern in mind
```

## Template 3: Floor Tiles

Use when generating custom floor tiles for your office background. Pixel-agents supports 9 floor variants.

```
Create a set of pixel art floor tiles for a tech command center office.

Tile dimensions: EXACTLY 16x16 pixels per tile. This is non-negotiable.
Arrange all tiles in a single horizontal row, left to right, with no gaps.

Tiles (left to right):
1. Dark industrial floor — near-black (#050505) with subtle pixel texture
2. Dark floor with green accent line — single #4ADE80 pixel stripe across center
3. Dark floor with cable channel — recessed groove with visible cable pixels
4. Metal grating floor — grid pattern suggesting ventilation/industrial grating
5. Carpet/mat tile — slightly warmer dark tone for desk areas
6. Transition tile — edge piece between floor types (half dark, half grating)
7. Worn/damaged floor — same base as tile 1 but with scuff marks or lighter patches
8. Highlight floor — tile with subtle green (#4ADE80) corner accent for pathways
9. Plain dark tile — solid dark (#0A0A0A), simplest variant

All tiles must connect seamlessly when placed adjacent to each other horizontally
and vertically. Edges must match their neighbors.

Perspective: Flat top-down view. NOT isometric. Looking straight down at the floor.

Style: Pixel art. Muted, dark color palette. Subtle variation — these are floor tiles,
not the focal point. They should read as "dark tech floor" at a glance.

Technical: 144x16 pixel final image (9 tiles at 16x16). Transparent background
where applicable, or solid dark fill. No anti-aliasing.
```

## Template 4: Wall Tileset (Bitmask Auto-Tile)

Use when generating wall tiles. Pixel-agents uses a 16-sprite bitmask system where each sprite represents a different neighbor configuration: N=1, E=2, S=4, W=8.

```
Create a pixel art wall tileset using the bitmask auto-tiling convention.

The tileset contains 16 wall sprites, one for each combination of cardinal neighbors.
Each sprite is 16 pixels wide. Wall sprites are TALLER than floor tiles — 16x32 pixels
(they extend upward to show wall height).

Arrange all 16 sprites in a 4x4 grid (4 columns, 4 rows), each cell 16x32 pixels.

Bitmask index (row-major order, 0-15):
- 0: No neighbors (isolated wall pillar)
- 1: North neighbor only (wall continues upward)
- 2: East neighbor only (wall continues right)
- 3: North + East
- 4: South neighbor only (wall continues downward)
- 5: North + South (vertical corridor wall)
- 6: East + South
- 7: North + East + South
- 8: West neighbor only (wall continues left)
- 9: North + West
- 10: East + West (horizontal corridor wall)
- 11: North + East + West
- 12: South + West
- 13: North + South + West
- 14: East + South + West
- 15: All four neighbors (center piece)

Wall style: Dark tech/industrial walls for a command center. Base color dark blue-gray
(#1A1A2E) with subtle panel lines. Where a wall has NO neighbor on a side, that edge
should show a visible wall face/edge. Where it DOES have a neighbor, the edge should
connect seamlessly.

Perspective: Top-down orthogonal. Walls are viewed from above but show vertical height
(the 32px height represents wall rising up from the 16x16 floor grid).

Technical: Final image is 64x128 pixels (4 columns of 16px, 4 rows of 32px).
No anti-aliasing. Dark color palette. Subtle green (#4ADE80) accent lighting on edges.
```

```
Create a pixel art furniture sprite for a tech command center office.

Furniture item: [ITEM — e.g., "desk with dual monitors", "ergonomic office chair",
"server rack with blinking LEDs", "standing terminal console"]

Dimensions: The item should fit within a [WIDTH]x[HEIGHT] pixel bounding box, where
width and height are multiples of 16 (the tile size). Common sizes:
- Small items (chair, plant, bin): 16x32 or 16x16
- Medium items (desk, bookshelf): 32x32 or 48x32

Anchor point: Bottom-center of the sprite. The renderer places furniture by anchoring

Perspective: Top-down orthogonal — NOT isometric. Furniture is viewed from straight above
with a slight front-face tilt (you can see the front face of a desk, not just the top).

while being positioned on a flat grid.

[VARIANT — if the item has multiple views]:
Generate two variants side by side:
- FRONT view: Item facing the viewer (e.g., front of desk with monitor screens visible)
- SIDE view: Item rotated 90 degrees (e.g., side profile of desk)

Style: 16-bit pixel art. Dark color palette matching the command center theme.
Equipment surfaces in medium gray (#374151, #6B7280).
Monitor screens glow neon green (#4ADE80).
LED indicator lights in orange (#F97316) or green (#4ADE80).
Clean dark outlines (#272929, 1px).

Technical: Transparent background. No anti-aliasing. No gradients.
Crisp pixel edges. Item must look correct when placed on a dark (#050505) floor.
```

## Prompt Refinement Tips

### If the model produces "isometric" perspective:
Add: "CRITICAL: This is a FLAT top-down orthogonal view. The camera looks STRAIGHT DOWN. There is NO angle, NO isometric tilt, NO vanishing point. All horizontal lines are perfectly horizontal. All vertical lines are perfectly vertical."

### If character sprites aren't 16x32:
Add: "The final sprite MUST be EXACTLY 16 pixels wide and 32 pixels tall. Count the pixels. The character fills this 16x32 canvas with feet near the bottom edge and head near the top edge. Do NOT add padding or margins."

### If the output looks like a shrunken illustration instead of pixel art:
Add: "This is TRUE pixel art at native resolution. Every individual pixel must be intentionally placed. At 16x32 pixels, a character's eye might be a single pixel. Hair is 3-5 pixels across. There is no room for smooth curves — everything is blocky, angular pixel construction."

### If anti-aliasing creeps in:
Add: "ABSOLUTELY NO anti-aliasing. Every pixel boundary is a hard, binary edge. Adjacent pixels are fully opaque distinct colors — never a blended intermediate. If you zoom in 800%, every pixel should be a clean square of a single solid color."

### If sprite sheet frames are inconsistent:
Add: "The character's head must be at the EXACT same Y position in every frame. Feet land on the EXACT same ground line. Body width stays identical. Only limbs and minor features change between frames. Overlay the frames mentally — the silhouette should barely change."

### If using a reference photo and the character isn't recognizable:
Add: "Focus on the 2-3 most recognizable features of this person that can be expressed in pixels: [e.g., 'distinctive curly dark hair (3 pixels tall above head), glasses (2 bright pixels at eye level), always wears red hoodie']. At 16x32, recognition comes from signature details, not facial accuracy."

## Generation Workflow for a Complete Custom Office

Generate assets in this order for best results:

1. **Characters first** — Generate each person's base sprite (Template 1), get them right before anything else. This is the hardest part because likenesses matter.

2. **Character animations** — Once the base sprite looks good, generate the full sprite sheet (Template 2) referencing the approved base sprite for consistency.

3. **Floor tiles** — Generate the 9 floor tile variants (Template 3). These are simple and foundational.

4. **Wall tileset** — Generate the 16-sprite bitmask wall sheet (Template 4). Test that connections look right.

5. **Furniture** — Generate each piece individually (Template 5). Start with desks and chairs since characters interact with them directly.

6. **Screen content** — Generate monitor displays last (Template 6) since they're composited onto furniture.

7. **Full layout** — Optionally generate a complete background (Template 7) as a reference, or assemble from tiles in code.

### Post-Generation Checklist

- [ ] Character sprites are exactly 16x32 pixels
- [ ] Floor tiles are exactly 16x16 pixels
- [ ] Wall sprites use the correct bitmask convention
- [ ] Furniture anchors at bottom-center correctly
- [ ] All assets use transparent backgrounds
- [ ] No anti-aliasing anywhere
- [ ] Color palette matches Zone 2 theme
- [ ] Characters are visually distinguishable from each other at 1x zoom
